# STEMBridge Design System

> Single source of truth for UI tokens, components, and design principles for the frontend.
> Tokens are defined in `app/globals.css`, generated by shadcn/ui's `init` and extended via `@theme inline`. The variable names (`--primary`, `--accent`, `--destructive`, etc.) already exist with grayscale placeholder values — this doc specifies what to set them *to*, not a parallel token set to invent.
> Do not hardcode hex values, spacing, or radii in feature code once tokens exist for them.

---

## Design Principles

- **Patient, not flashy.** The product's whole pitch is "a patient teacher." Calm pacing, no aggressive motion, no pressure-inducing countdown timers on core learning flows.
- **Readable by a weak reader.** Plain language, short sentences in UI copy, generous line-height, no dense paragraphs. Icons and visuals carry meaning alongside text, never instead of accessible text.
- **Encouraging, never punishing.** Wrong answers get a gentle, explanatory tone — never red error-flooding. Save strong red/error styling for system states (no connection, broken input), not for "you got it wrong."
- **Low-end-device honest.** No effect that costs more than it's worth on a cheap Android device: minimal blur, minimal large shadows, no heavy parallax.
- **Mobile-first.** Most target devices are phones or shared low-spec tablets/laptops. Design for small screens first, scale up.
- **Accessible by default.** Minimum 4.5:1 text contrast (WCAG AA). Full keyboard navigation. Works with the voice/audio layer, not against it (don't bury read-aloud controls).

---

## Creative Direction (Brief)

- **Mood:** Warm, encouraging, a little playful — but not loud or cluttered. Think "friendly classroom poster," not "kids' game app."
- **Color use:** One confident primary brand color, one warm accent for gamification (badges, streaks), generous neutral space around content so the page never feels noisy.
- **Typography voice:** Clear, rounded-but-legible headings; simple, highly legible body text — this is read by JSS 1 students, some with weak reading skills.
- **Density:** Spacious. Avoid dashboard-style density anywhere a student is the audience (Teacher Dashboard can be denser — it's an adult, data-literate audience).

## Color Palette

This project runs on **shadcn/ui**, which already established its own CSS-variable token set in `app/globals.css` (`--primary`, `--secondary`, `--accent`, `--destructive`, `--muted`, `--border`, `--ring`, `--card`, etc., all defined as `oklch()` values, light + `.dark` variants, wired into Tailwind via `@theme inline`). **Use those variables — don't invent a parallel `--color-brand-*` set that fights with them.**

shadcn's defaults out of the box are grayscale (`baseColor: neutral`, all `oklch(... 0 0)`). The work here is to set real brand values into shadcn's existing variables, plus add the handful of education-specific tokens shadcn doesn't provide.

### Map Brand Color Onto Existing shadcn Variables

| shadcn Token | Set To | Use |
|---|---|---|
| `--primary` | Brand blue, e.g. `oklch(0.55 0.18 255)` (~`#2563eb`) | Primary actions, links, focus accents |
| `--primary-foreground` | Near-white | Text/icons on `--primary` |
| `--secondary` | Soft neutral tint | Supporting actions |
| `--accent` | Warm amber, e.g. `oklch(0.75 0.15 70)` (~`#f59e0b`) | Gamification — badges, streaks, rewards |
| `--accent-foreground` | Near-black | Text/icons on `--accent` |
| `--destructive` | Reserve for **system errors only** (broken input, failed sync) | Never used for "incorrect answer" feedback — see Enforcement |
| `--ring` | Match `--primary` | Focus ring color |
| `--card` / `--background` | Keep shadcn's neutral light/dark pair | Page and card surfaces |

Edit these directly in `app/globals.css` under `:root` and `.dark` — do not redefine them a second time under a different token name.

### Additional Tokens (Not in shadcn by Default)

shadcn ships no concept of "success" or a separate gamification-vs-brand split. Add these alongside the existing `@theme inline` block:

| Token | Default | Use |
|---|---|---|
| `--success` | `oklch(0.6 0.15 145)` (~`#16a34a`) | Correct answers, completed lessons, sync success |
| `--success-foreground` | Near-white | Text/icons on `--success` |
| `--warning` | Same value as `--accent` (~`#f59e0b`) | Offline indicator, gentle nudge states |

Do not add a separate full neutral/info scale — shadcn's `--muted`/`--muted-foreground` and `--border` already cover secondary text and dividers. Reach for those before introducing a new token.

Dark mode is secondary for this product (most usage is daytime, shared classroom devices) but shadcn already wires up `.dark` overrides for every variable — keep them filled in for consistency rather than leaving them as the generated grayscale defaults.

## Typography

| Token | Size | Line Height | Weight | Use |
|---|---|---|---|---|
| `h1` | 2rem | 1.25 | 700 | Page title |
| `h2` | 1.5rem | 1.3 | 700 | Section heading (lesson title) |
| `h3` | 1.25rem | 1.4 | 600 | Card title |
| `body-lg` | 1.125rem | 1.7 | 400 | Step-by-step solver text, lesson explanations |
| `base` | 1rem | 1.6 | 400 | Standard body |
| `sm` | 0.875rem | 1.5 | 400 | Secondary / metadata |
| `label` | 0.875rem | 1.3 | 500 | Form field labels |

Rules:

- Default body size starts at `base` (1rem) minimum anywhere a student reads instructional text — never drop below that for primary content.
- `body-lg` is the default for solver steps and lesson explanations specifically, since reading ease matters most there.
- Headings use `text-wrap: balance`; paragraphs use `text-wrap: pretty`.

## Radius & Elevation

shadcn already derives `--radius-sm` / `--radius-md` / `--radius-lg` / `--radius-xl` etc. from a single `--radius` base variable in `globals.css`. Use those — don't define a second radius scale. The default base (`--radius: 0.625rem` = 10px) reads slightly clinical for a kids' product; consider bumping it toward `0.75rem`–`0.875rem` for a softer, friendlier feel across every component at once.

| Use | Token |
|---|---|
| Inputs, small buttons | `--radius-sm` |
| Cards (lesson cards, quiz cards) | `--radius-md` |
| Modals, dialogs | `--radius-lg` |
| Badges, avatars, pills | `rounded-full` (Tailwind utility, not a radius token) |

Keep shadows minimal — one soft elevation level for cards, one for modals. Heavy shadow stacks cost paint performance on low-end devices for no real benefit here.

| Token | Use |
|---|---|
| `elevation-1` | Cards |
| `elevation-2` | Modals / dialogs |

## Motion

Motion should feel calm and confirming, never bouncy or attention-grabbing for its own sake.

| Token | Duration | Use |
|---|---|---|
| `fast` | 120ms | Button hover/press feedback |
| `base` | 200ms | Standard transitions, step reveal |
| `slow` | 320ms | Modal open/close, badge celebration moment |

- Respect `prefers-reduced-motion` globally.
- The one place a slightly more expressive animation is earned: revealing a new badge/achievement. Keep it brief (under 1s) and skippable.

## Core Components Needed (Education-Specific)

Standard primitives (Button, Input, Dialog, etc.) come from shadcn — generate with `npx shadcn@latest add <component>` rather than hand-building. Beyond those, this product needs custom, education-specific components:

- **StepCard** — renders one step of the solver's explanation, supports progressive reveal.
- **EquationInput** — input surface for math expressions, with clear formatting feedback (not raw text-only).
- **GeometryCanvas** — draggable-parameter shape visualization (circle, etc.), takes a config prop, emits live values.
- **VoicePlaybackButton** — play/pause/replay control for read-aloud, with a clear playing state.
- **AchievementBadge** — badge/streak/level display, used in both student profile and the celebratory unlock moment.
- **ProgressBar / TopicMasteryIndicator** — visual indicator of mastery per topic, used by both student progress views and (later) the Teacher Dashboard.
- **OfflineIndicator** — persistent, non-alarming indicator of online/offline + sync state. Should read as informative, not as an error banner.

Each should be built on tokens only, sized and spaced per the scales above, and documented with props in-component.

## Accessibility Standards

| Rule | Requirement |
|---|---|
| Contrast | 4.5:1 minimum for text (WCAG AA) |
| Focus states | Visible on all interactive elements |
| Keyboard access | Full navigation via keyboard |
| Screen readers | Semantic HTML + ARIA; especially important since some students are weak readers and may rely on voice/audio + screen reader together |
| Motion | Respect `prefers-reduced-motion` |
| Icon-only buttons | Must include `aria-label` (e.g. voice playback controls) |

## Enforcement

| Category | Rule |
|---|---|
| Colors | Tokens only. No hex in feature code. |
| Typography | Semantic type scale roles only. |
| Spacing | 8px-based token system only. |
| Motion | Defined duration tokens only; nothing bouncy outside the badge-unlock moment. |
| "Wrong answer" states | Never styled with `--destructive`. Use a neutral/encouraging treatment instead — reserve `--destructive` for system errors. |
